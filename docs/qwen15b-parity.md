# Qwen2.5-1.5B-Instruct on the Neural Engine: measured parity

Espresso runs Qwen2.5-1.5B-Instruct through its ANE hybrid decode path. Phase 2
proved the 28 QKV+FFN kernels compile. This document is the correctness follow-up:
the shipping generate path was emitting `!!!!!!!!` (token 0) until fp16 RMSNorm
`mean(x^2)` overflow was fixed.

Everything here is measured on Apple M-series hardware with
`ESPRESSO_REALMODEL_DISABLE_HYBRID_FALLBACK=1`. Every number has a command that
regenerates it.

## Reproducing from a clean clone

```bash
# 1. Download the checkpoint, convert bf16 -> fp16 blobs, pack the .esp bundle
python3 scripts/convert_qwen25_05b_to_esp.py --model Qwen/Qwen2.5-1.5B-Instruct

# 2. Generate on the ANE, refusing any fallback
ESPRESSO_REALMODEL_DISABLE_HYBRID_FALLBACK=1 \
  ./espresso generate --model ~/Library/Caches/Espresso/qwen25-15b/Qwen2.5-1.5B-Instruct.esp \
  --no-tui -n 8 "The capital of France is"

# 3. Per-layer parity report (writes docs/qwen15b-layer-parity.json)
python3 scripts/qwen25_pytorch_reference.py --model Qwen/Qwen2.5-1.5B-Instruct layer-parity \
  --backends cpu-fp32 cpu-fp16 ane \
  --max-positions 8 \
  --report-json docs/qwen15b-layer-parity.json \
  --report-markdown docs/qwen15b-parity-layers.md

# 4. End-to-end logit parity (writes docs/qwen15b-logit-parity.json)
python3 scripts/qwen25_pytorch_reference.py --model Qwen/Qwen2.5-1.5B-Instruct logit-parity \
  --backends cpu-fp32 ane \
  --fixture Tests/RealModelInferenceTests/Fixtures/qwen25-15b-greedy-reference.json \
  --report-json docs/qwen15b-logit-parity.json

# 5. Greedy token parity against the committed PyTorch fixture
# Run 0.5B and 1.5B in separate processes. One process compiling both
# models exhausts the per-process ANE compile budget.
ANE_HARDWARE_TESTS=1 ESPRESSO_REALMODEL_DISABLE_HYBRID_FALLBACK=1 \
  swift test --filter test_qwenGreedyParityMatchesPyTorchReferenceOnANE
ANE_HARDWARE_TESTS=1 ESPRESSO_REALMODEL_DISABLE_HYBRID_FALLBACK=1 \
  swift test --filter test_qwenGreedyParity15bMatchesPyTorchReferenceOnANE
```

The converter and the reference script both bootstrap a managed Python venv when
`torch` and `transformers` are missing.

## What was broken

Token 0 in the Qwen tokenizer is `!`. Eight decode steps of argmax-0 printed
`!!!!!!!!`. Teacher-forced layer isolation showed:

| Check | Result |
| --- | --- |
| CPU-exact vs PyTorch at layer 0 | max abs 3.64e-5, relative 3.69e-6 — layout / RoPE / QKV-bias / residual are right |
| ANE vs PyTorch at layer 0–2 | finite, same order as 0.5B |
| ANE vs PyTorch at layer 3–26 | Inf on position 0 until RMSNorm was scaled |

Position 0 of layer 3 has residual RMS ≈ 270. fp16 `mean(x^2)` overflows when
RMS > ~256 (65504). Layer 2 sits at RMS ≈ 124 and was fine; layer 3 is the first
layer over the cliff. Overflowed Q/K/V poisoned the KV cache, so every later
token was garbage and the LM head's argmax collapsed to 0.

`ESPRESSO_RMSNORM_USE_FP32=1` already existed, but ANE rejected that MIL on
ios18 (`InvalidMILProgram`: fp32 casts plus fp16 scalars). The default is now a
**scaled fp16 RMSNorm**: `xs = x * 1/4`, then `mean(xs^2)`. That keeps the
compiling fp16 op set and holds mean-square at ~4500 for RMS 270. Opt out with
`ESPRESSO_RMSNORM_USE_FP16=1` only to reproduce the overflow.

## Per-layer parity

Full tables are in [`qwen15b-parity-layers.md`](qwen15b-parity-layers.md). Each
layer is fed the *reference* input hidden states for every position.

| Backend | worst layer | max abs diff | worst relative to layer scale |
| --- | --- | --- | --- |
| `cpu-fp32` (Espresso's CPU oracle) | 26 | 2.59e-2 | 1.26e-4 |
| `cpu-fp16` (fp32 accumulation, fp16 intermediates) | 7 | 3.12e+0 | 4.72e-4 |
| `ane` (hybrid kernels, scaled RMSNorm) | 26 | 7.24e+0 | 3.54e-2 |

The fp32 CPU column is the architecture check: RoPE (theta = 1e6), GQA
(12 Q heads over 2 KV heads, headDim=128), RMSNorm epsilon, SwiGLU, and Q/K/V
biases are right. Layer 0 relative error is 3.7e-6, far below the 1e-3 stop
condition.

The residual stream reaches ~6600 by the middle layers (larger than 0.5B's
~1700). fp16 spacing at that magnitude is 4.0, which is what the fp16/ANE
absolute columns show. Layer 26's 3.5% relative is against a *small* residual
scale (~205) after the stream collapses toward the final layers.

## End-to-end logit parity

The table below is **not** the served `cpu_fp16_tiled` generate classifier. It
is the Swift layer probe in `--chain` mode plus a NumPy/Python LM head.
Regenerated by `scripts/qwen25_pytorch_reference.py --model Qwen/Qwen2.5-1.5B-Instruct logit-parity`.
Recorded in [`qwen15b-logit-parity.json`](qwen15b-logit-parity.json).

The first measurement covers fixture cases 0 and 5 (full 12 is expensive: each
`swift run EspressoQwenParity` recompiles). Argmax agreed on all four
backend/case pairs.

| Case | Backend | max \|dlogit\| | argmax vs ref | ref top-1/top-2 gap |
| --- | --- | --- | --- | --- |
| 0 | cpu-fp32 | 3.08e-4 | 32 = 32 | 0.561 |
| 0 | ane | 0.209 | 32 = 32 | 0.561 |
| 5 | cpu-fp32 | 3.37e-4 | 785 = 785 | 0.829 |
| 5 | ane | 0.239 | 785 = 785 | 0.829 |

Worst ANE `|dlogit|` = **0.239**. That is the greedy-suite `maxObservedANELogitError`
floor: a flip is allowed only if it is the reference runner-up *and* the
reference gap is ≤ 0.24. Any other mismatch fails the test.

## Greedy token parity

`Tests/RealModelInferenceTests/QwenParityExactMatchTests.swift` opens the packed
`.esp` through `ESPRuntimeBundle` and drives generation from the fixture's
prompt token IDs over 12 prompts × 32 tokens:

```
scripts/qwen25_pytorch_reference.py --model Qwen/Qwen2.5-1.5B-Instruct fixtures \
  --output Tests/RealModelInferenceTests/Fixtures/qwen25-15b-greedy-reference.json \
  --max-new-tokens 32
```

Measured on the packed `.esp` with fallback disabled (2026-08-14):

```
exact cases 9/12   matching-prefix tokens 328/384   path=hybrid   head=cpu_fp16_tiled
```

Three divergences, all runner-up near-ties inside the 0.239 ANE logit error:

| Case | Diverges at | Reference top-1 / runner-up | Reference top-1/top-2 gap | Runtime chose |
| --- | --- | --- | --- | --- |
| 3 | token 5/32 | 5392 / 949 | **0.046** | 949 (the runner-up) |
| 9 | token 30/32 | 304 / 15503 | **0.080** | 15503 (the runner-up) |
| 11 | token 5/32 | 1657 / 6366 | **0.024** | 6366 (the runner-up) |

The contract is the same as 0.5B: every divergence must (a) be the reference's
own runner-up and (b) occur at a top-1/top-2 gap within the measured ANE logit
error. A divergence at a wider gap, or to any other token, fails the test.

France prompt after the RMSNorm fix (n=8, hybrid, fallback disabled):

```
The capital of France is Paris.
```

`decode_path=hybrid`, `compile_retries=0`, `compile_failures=0`,
`exact_head_backend=cpu_fp16_tiled`. No tok/s, binding, or LM-head backend
change was made in this phase.

## Reference oracle: two traps worth knowing

1. **`model.generate(do_sample=False)` is not pure greedy.** Qwen2.5's
   `generation_config.json` sets `repetition_penalty: 1.1`, and `generate`
   applies its logits processors regardless of sampling. The reference uses an
   explicit argmax loop over raw logits instead.
2. **`output_hidden_states` does not give you layer boundaries.** HuggingFace
   applies the final norm before the last entry. The script uses forward hooks
   to capture true pre/post-layer states.

## ANE limitations hit, and what was done about each

| Limitation | Resolution |
| --- | --- |
| fp16 `mean(x^2)` overflows when residual RMS > ~256 (1.5B layer 3+) | Default RMSNorm scales the residual by 1/4 before squaring; unscaled path is `ESPRESSO_RMSNORM_USE_FP16=1` |
| In-graph fp32 RMSNorm (`ESPRESSO_RMSNORM_USE_FP32=1`) is `InvalidMILProgram` on ios18 | Left as an experiment; not the default |
| LM head too large for ANE SRAM (151936 × 1536 ≈ 467 MB) | Stays on CPU (`cpu_fp16_tiled`) |
| Donor delta misses at this FFN width (`hiddenDim * dModel > 12M`) | Disabled; each FFN compiles from scratch |
| Compiling hybrid kernels ≠ correct hidden states | This document; LFM2 already recorded the same lesson |

## Known gaps

- Greedy only. No sampling parity claim.
- Logit-parity JSON currently covers fixture cases 0 and 5 (full 12 is expensive:
  each `swift run EspressoQwenParity` recompiles). Worst ANE `|dlogit|` on that
  subset is 0.239.
- Attention, RoPE, and the LM head run off the ANE by design.
- No throughput claim is made here. Parity was the deliverable.
